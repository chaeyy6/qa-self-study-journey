# Creating a Scrum Project in Jira

## Learning Objective

Understand how software testing fits within an Agile environment, become familiar with Jira as an Agile project-management and issue-tracking tool, and learn the basic structure and configuration of a Scrum project.

## My Understanding

Before this lesson, I understood software testing mainly as a set of activities such as creating test cases, executing tests, and reporting defects. I learned that these same testing practices continue to be used in Agile development, but they are performed within an iterative and collaborative project-management process.

I also learned how Jira organizes software development work using different issue types. An Epic can represent a large feature or initiative, which can be broken down into Stories, Tasks, and Sub-tasks. Bugs are used to track defects or unexpected behavior.

A Scrum project organizes work into Sprints, where selected items from the Backlog are planned and worked on during a time-boxed iteration. Jira provides boards, workflows, and reports that help the team monitor the progress of this work.

---

## QA Perspective

As a QA Engineer, understanding how Jira organizes development work is important because testing activities are closely connected to the team's requirements and workflow.

A tester may use Jira to review user stories and acceptance criteria, track testing-related tasks, report defects, monitor the status of issues, and maintain traceability between requirements and testing activities.

The tester also needs to understand the team's workflow because testing may occur at different stages before an issue can be considered complete.

## Real-World Examples

- **Epic:** User Account Management
  - Story: User Sign-Up
  - Story: User Login
  - Story: Password Reset

- **User Story:** As a user, I want to log in using my credentials so that I can access my account.

- **Testing Task:** Review acceptance criteria for the Login feature.

- **Sub-task:** Execute login test cases.

- **Bug:** Login accepts an incorrect password.

- **Example Workflow:**
  - To Do
  - In Progress
  - Pending Retest
  - Done

- **Confluence:** Store project documentation such as requirements, meeting notes, and other project information.

- **Jira:** Manage and track project work, requirements, development tasks, testing activities, and defects.

## Key Takeaways

- Agile does not fundamentally change the purpose of software testing; traditional testing activities are still performed within the Agile process.
- Jira is commonly used to plan, track, and manage software development work.
- Jira organizes work through issue types such as Epics, Stories, Tasks, Sub-tasks, and Bugs.
- A Scrum project organizes development work into time-boxed Sprints.
- The Backlog contains work that can be prioritized and selected for future Sprints.
- Jira workflows help teams track the progress of development and testing activities.
- QA Engineers use Jira to work with requirements, track testing-related work, report defects, and maintain traceability.
- Confluence and Jira can work together, with Confluence primarily supporting documentation and Jira primarily supporting project and work management.
- Understanding Jira is important for QA Engineers working in Agile development teams.
